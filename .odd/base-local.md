## Acceptance criteria
- El entorno local arranca con instrucciones reproducibles y servicios aislados por proyecto, expuestos solo a loopback.
- PostgreSQL aplica migraciones y tiene disponible pgvector; comprobar una operación vectorial sintética, sin afirmar RAG implementado.
- API valida fechas con zona horaria, conserva la identidad externa y guarda evento/outbox atómicamente antes de confirmar recepción.
- Una reentrega idéntica no duplica eventos, actividades ni tareas; una identidad reutilizada con contenido diferente se rechaza explícitamente.
- Worker procesa desde persistencia. Reinicio/fallo transaccional permite retomar sin proyección parcial o efectos duplicados. No hace llamadas externas ni depende de una conversación abierta.
- Clasificación determinista limitada a la demo, claramente rotulada; agradecimientos no generan tareas, contexto faltante queda visible y respuestas de hilos actualizan el pendiente sin requerir nueva mención. No cerrar tareas automáticamente.
- Panel permite probar fixtures, ver pendientes/hilos/fuente y distingue vacío, error y carga; funciona en pantalla pequeña y teclado.
- Pruebas obligatorias: backend unit/integration con PostgreSQL, lint backend, build/typecheck y pruebas frontend, configuración Compose, smoke de API/worker/panel y revisión de alcance exacto. Clasificar comandos antes de ejecutarlos.
