# n8n local de prueba

## Objective
Añadir n8n al entorno local para probar workflows sin Slack, credenciales corporativas ni modelos.

## Problem
Se necesita un laboratorio local para explorar automatización determinista. La autorización Slack sigue diferida y no se resuelve instalando n8n.

## Scope
- In scope: servicio Compose opt-in con imagen oficial fijada, volumen SQLite propio, loopback y red separada; comandos de operación; ejemplo manual sintético; pruebas y verificación de salud/UI.
- Out of scope: Slack real, MCP, llamadas Claude/Codex, polling/schedules/webhooks, túneles, publicación, acceso a DB/API del producto, instalación global, Git y cambios en servicios existentes.

## Authorized scope
Solicitud del usuario: «Ok, podrías agregar un n8n para probar». Confirmación posterior: «Termina de configurar n8n en local y verifica que arranque junto con el proyecto». Se mantiene el alcance opt-in: coexistir con la base no autoriza modificar make up ni conectar Slack. Archivos permitidos: compose.n8n.yaml, Makefile, README.md, docs/n8n-local.md, docs/examples/n8n-local-smoke.workflow.json, tests/test_n8n_local.py y este tracking. Solo servicio n8n dentro del proyecto Docker efren-bot. No tocar Compose base, .env, credenciales, API/worker/web/DB, puente Claude o proxy Slack pausado.

## TDD
Standard: validación estática del workflow/aislamiento, Compose y checks Python afectados, después runtime real. No ejecutar pruebas DB/frontend completas sin un cambio que las requiera.

## Delivery
Checkout main existente y cambios previos intactos. Sin staging, commits, ramas o push. Delta/riesgo formal pendiente de aislamiento exacto; no sustituirlo con una revisión informal ni declarar cierre global.

## Acceptance criteria
- Imagen docker.n8n.io/n8nio/n8n:2.44.6 fijada también al digest del índice sha256:d02752c6ab446ae9db8deec2f9cc887c378f77cdcad31650814df936b7386dfb.
- Publicación exclusivamente 127.0.0.1:5678, volumen propio /home/node/.n8n, red propia sin acceso a la red default del producto; sin env_file, HOME, Docker socket ni secretos.
- Arranque/parada dirigidos solo a n8n, sin recrear servicios previos ni borrar volúmenes. Cuenta local n8n a cargo del usuario, sin desactivar autenticación.
- Ejemplo inactivo de disparador manual y datos ficticios, sin red/código arbitrario/credenciales/activación automática. Importación/ejecución reales pendientes si requieren que el usuario complete la cuenta inicial.
- Salud, readiness y UI observadas, aislamiento inspeccionado y reinicio conservando volumen/configuración probado. Distinguir estos resultados de ejecutar el workflow.

## Findings & adjustments
- El pedido de n8n no reabre creación de app Slack ni autenticación del proxy, diferidas por el usuario.
- Se sigue el patrón de override opt-in del repositorio. make up existente no cambia; la nueva operación apunta solo al servicio n8n.
- Consultas documentales obligatorias por configuración/versiones confirmaron que una instancia nueva necesita crear su owner antes de importar con CLI. No automatizar credenciales ni saltarse la autenticación.
- Checkpoint documental previo al arranque: evidencia comunicada por writer y parent; este checkpoint no ejecuta servicios ni repite pruebas. n8n todavía no se ha arrancado; tareas 3 y 4 siguen pendientes.
- Actualización posterior al checkpoint: el arranque interno healthy inicial no publicó realmente el puerto en Docker Desktop con la red internal:true. Writer cambió únicamente compose.n8n.yaml, README.md y docs/n8n-local.md a bridge dedicada internal:false. Permite salida externa; no es airgap ni bloqueo Slack. No se añadieron proxies, servicios ni reglas de firewall; la red default del producto sigue excluida.
- Diagnóstico de persistencia: HostConfig.Binds contiene la notación del volumen nombrado efren-bot_n8n-data:/home/node/.n8n:rw; Mounts confirma Type=volume, no bind del host. El criterio es ausencia de montajes de host, no exigir erróneamente que esa lista de Docker esté vacía. No se modificó configuración para satisfacer el verificador.
