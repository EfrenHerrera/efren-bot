# OpenChamber Slack MCP proxy

## Objective
Corregir los logs sensibles del proxy solicitado, conectarlo al OpenCode integrado en OpenChamber y verificar únicamente conexión/metadatos Slack.

## Problem
El proxy upstream registra callbacks OAuth con code/state y no oculta code_verifier. La autorización Slack para este cliente aún no está acreditada.

## Scope
- In scope: instalación host aislada, redacción de logs y pruebas, conexión MCP local de OpenChamber, login interactivo del usuario y verificación de metadatos.
- Out of scope: leer/publicar mensajes, escucha Slack, cambios en Efren Bot API/DB/worker/fixtures, credenciales de Claude, uso de identificadores partner sin autorización, Git y despliegues Docker.

## Authorized scope
Petición explícita del usuario 2026-10-23: «Corrige los logs sensibles del proxy y conéctalo a OpenChamber; luego verifica la conexión con Slack». Autoriza una copia host bajo `.local/slack-mcp-proxy/`, cambios acotados a redacción/pruebas y entrada MCP global preservando configuración ajena. No modifica el alcance de la demo ni del bridge Claude. No usar secretos en chat/logs; autenticación humana si hace falta. No autoriza alterar políticas del workspace ni reutilizar la identidad de otra aplicación.

## TDD
Standard con regresión específica red -> fix -> pass para secretos y pruebas upstream existentes; después comprobaciones de runtime sin contenido Slack.

## Delivery
Sesión en main; sin staging, commits, ramas, push ni migración/upgrade. Fuente upstream fijada a d056996bc99d0571ce6ddf396622dbb2371b8254, copia local ignorada por Git/Docker. Evaluación formal de riesgo pendiente: el delta de una instalación ignorada/global no queda aislado por --base-ref; no declarar cierre global verificado.

## Acceptance criteria
- Logs no contienen códigos, state, PKCE verifier, tokens, cookies o secretos; pruebas adversariales y regresión upstream.
- Listeners solo loopback, sin nuevos datos/credenciales dentro de Docker.
- OpenChamber usa su OpenCode v2.1.3 integrado, no el 1.18.31 del PATH.
- Entrada MCP preserva configuración existente. No copiar credenciales/identidad de Claude ni adivinar autorización Slack.
- Estado conectado y catálogo MCP comprobados con el runtime real, o bloqueo exacto y login pendiente explícitos. Nunca llamar herramientas Slack de contenido para probar conexión.
